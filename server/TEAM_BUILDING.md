# 팀 빌딩 운영

## 지원과 모집

- `POST /team-build/apply/submit`, `GET /team-build/{projectId}/applies`, `POST /team-build/recruit/submit`은 `round=1|2`를 받는다. 생략하면 1이다.
- 지원·모집 제출은 현재 운영 차수와 상태가 일치해야 한다.
- 지원자는 차수별 최대 5개의 서로 다른 `(프로젝트, 직무)` 조합을 제출할 수 있다. 여러 번 제출해도 합계가 5개를 넘을 수 없다. 목록 순서가 지원 우선순위다.
- `experience`를 저장하고 지원 조회에 반환한다. 기존 `career` 요청·응답도 호환되며 둘 다 제출하면 `experience`가 우선한다. DB는 기존 `career` 컬럼을 사용한다.
- 직무 입력은 대소문자를 구분하지 않는다. 기존 응답의 대문자 직무 표기는 유지한다.
- 1차 팀장은 모든 직무를 합쳐 서로 다른 지원자를 최소 `min(4, 전체 지원자 수)`명 선택해야 한다. 한 사람의 여러 직무 지원은 한 명으로 센다.
- 2차는 선택 인원 하한이 없다. 빈 목록과 전원 선택 모두 가능하다. 두 차수 모두 실제 해당 직무 지원자만 선택할 수 있다.

## 1·2차 운영

기존 관리자 API 형식을 유지한다.

1. 학기 팀 빌딩을 열고 기존 상태 변경 API로 `APPLY → RECRUIT → CLOSED`를 진행한다.
2. `POST /admin/team/building/run`으로 1차를 배정한다.
3. 완료 후 기존 상태 변경 API로 `CLOSED → APPLY`를 요청하면 자동으로 2차로 넘어간다.
4. `round=2`로 지원·모집을 받으며 `RECRUIT → CLOSED` 후 동일한 실행 API로 2차를 배정한다.

`GET /team-build/apply/status`의 응답 형식은 동일하고 현재 운영 차수의 지원 여부를 반환한다. 완료한 차수의 배정은 재실행할 수 없다. 2차 모집 정원은 **추가로 모집할 인원**으로 해석한다. 1차 배정자는 유지되며 다음 차수에서 다시 배정하지 않는다. 팀장도 배정 후보에서 제외한다.

배정은 프로젝트·직무를 하나의 자리로 보고 팀장 우선순위로 제안한다. 여러 자리에서 선택된 지원자는 자신의 전체 지원 우선순위가 높은 자리 하나를 유지하고, 빈 자리는 다음 지원자로 채운다. 결과 조회는 지원서가 아닌 실제 팀 배정의 직무를 사용한다.

## 3차 서버 서비스

새 관리자 API는 노출하지 않는다. `ThirdRoundTeamBuildingService`를 Spring 빈으로 호출한다. 모든 변경은 2차 배정이 완료되고 상태가 `CLOSED`일 때만 가능하다.

- `rebuildClusters()`: 미배정 지원자를 분야별로 분류하여 저장한다. 기존 수동 수정을 초기화한다.
- `getClusters()`: 저장된 분류를 사용자 ID 순서로 조회한다.
- `updateClusters(Map<Long, Position>)`: 지정한 미배정자의 분야를 수동으로 수정한다. 포함하지 않은 사람의 분류는 유지한다.
- `allocate()`: 저장된 분류를 기준으로 분야별 남은 자리에 무작위 배정한다. 이후 재실행과 수정은 거부한다.

초기 분류는 가장 최근 지원 차수의 최우선 직무를 사용한다. 우선순위가 같은 과거 데이터는 직무 enum 순서, 프로젝트 ID 순서로 결정한다. 입력 조회 순서와 관계없이 같은 결과를 낸다. 경력 서술을 해석하는 AI 분류는 사용하지 않는다.

각 프로젝트·분야의 최신 모집 정원에서 그 모집 차수 이후 배정 인원을 뺀 자리에만 배정한다. 분야 안에서 지원자와 프로젝트 순서를 섞고 프로젝트를 순회하며 배정한다. 정원이 부족하거나 해당 분야 모집이 없으면 일부 인원은 미배정으로 남는다. 이미 배정된 사람과 팀장은 클러스터에서 제외한다.

## 검증 및 DB

`./gradlew test --offline --tests '*service.*'`로 서비스 테스트를 실행한다. 실제 DB 연결이 필요한 애플리케이션 컨텍스트 테스트와 운영 DB 마이그레이션은 별도로 실행해야 한다.

- V5: 지원·모집 차수, 기존 데이터는 1차.
- V6: 현재 차수·완료 차수 및 팀 배정 차수. 기존 팀 결과가 있는 학기는 1차 완료로 표시한다.
- V7: 수동 수정 가능한 분야 클러스터 저장.
